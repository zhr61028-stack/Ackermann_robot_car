# M3 小型粗路网驱动仿真闭环报告

2026-10-12。**结论：两条本地平面路网路线及一个行驶中不可达停车场景通过。不是完整 M3、校园 300 米或实车验收。** M0 仍为开发环境与通用仿真完成、硬件盘点待补。

## 本轮新增与复用

新增独立 `ackermann_route` 包、测试道路与路网、最小局部目标生成器及验证工具。复用 Gazebo 原生阿克曼组件、现有真值定位、Smac Hybrid-A*、RPP、模型与 60ms 指令超时保护，不安装软件。vehicle.yaml、nav2.yaml 与 guard.py 的内容校验全部相同，见[核验](原参数未变核验.json)。未修改 sources/、实车协议、NVIDIA 或系统配置，未提交或推送 Git。

## Route Server 接口与格式

已安装 Jazzy 的 nav2_route 1.3.13，无需跨发行版或源码混装。核对本机 nav2_msgs 的 ComputeRoute、ComputePathToPose、FollowPath 接口和官方 Jazzy 源码/文档：

- [官方 Jazzy Route Server 配置](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/route_server/configuring_route_server/)
- [官方 Jazzy Route README](https://raw.githubusercontent.com/ros-navigation/navigation2/jazzy/nav2_route/README.md)

GeoJSON FeatureCollection 中 Point 节点 properties 含 id、frame；MultiLineString 有向边含 id、startid、endid 和 metadata。节点与边 ID 唯一且不超过 uint16。本轮 frame=odom，数值为米，文件明确命名 LOCAL_METRIC_TEST_NOT_WGS84。这是 Route Server 支持的本地 TF 平面图，**不能当作标准 WGS-84 经纬度 GeoJSON**。Route Server 不会替本轮完成 GNSS 或经纬度投影。

ComputeRoute 接收节点起终点 ID，返回离散 Route 节点/边和稠密 nav_msgs/Path。DistanceScorer 根据边长和 metadata.speed_limit 比例计算代价；此字段在本轮是比例，不是 m/s。备选路段设 0.65，仅影响选路代价，不改变车速上限。Route Server 平滑转角（测试半径2.5m），生成可供局部目标采样的路线；**并未将该路线直接当作安全控制指令**。

局部目标生成器读取真值 odom，按路线弧长取前方4m目标和切线朝向。最近点搜索限定在既有进度附近，进度只向前；车辆按路线顺序进入路口2m范围才登记通过。前进约0.8m、且间隔至少1s后更新局部路径。目标交给 Smac 的 ComputePathToPose，再将可行路径交给 RPP 的 FollowPath；使用控制器正常路径替换，避免每个局部目标都先取消并停车。局部目标/路径均限制在当前位置各轴±5m，位于12×12m局部窗口内。

测试脚本**只提交终点 ID**，不提交中途路点，不发布行驶速度。节点起点由生成器依车辆位置选择；道路与路线决策来自 Route Server。

## 道路、分支与坐标

小场地约32×24m，道路宽6m（测试假设，非校园实测）。主干道两个路口位于(8,0)、(16,0)；另有经(8,8)的北侧备选分支。所有几何、路宽、起点与目标生成设置集中在 roads.yaml，图节点/有向边在 local_test_graph.geojson。

非道路区域在静态占据地图中为致命障碍，local/global costmap 均读取边界，Smac 不允许穿越未知区域。Gazebo 道路色块只是视觉标记，**不是实体围墙**。独立复核用保守完整车体矩形与道路并集补集做几何相交检查，不能只看车辆中心是否在道路内。运行时还检查车体离路和路线走廊偏离，异常则关闭速度转发。

定位为 TEST_GAZEBO_TRUTH；本地测试世界位置直接定义 odom，唯一动态定位变换为 odom→base_footprint，车体/车轮关系由 URDF 提供。原生轮式里程计仅作为 /wheel/odom 调试数据，frame=wheel_odom，不广播第二个定位 TF，不参与导航。ROS 使用 /clock 和 use_sim_time=true；速度转发依赖新消息和有效定位，底层保护器继续使用稳态时间判断超时。域84及独立 Gazebo partition 避免与原基础/简单场地模式串车。

最终校园粗地图只有道路中心线时，不能自然提供道路可通行边界；仍需明确可行驶区域来源、局部感知与边界约束。当前静态测试地图不能替代该工作。

## 验证结果

| 场景 | Route Server 节点顺序 | 终点位置误差 | 航向误差 | 路口顺序 | 完整车体离路/碰撞 | 中途持续停车 |
|---|---|---|---|---|---|---|
| A 西侧→东侧 | 1→2→3→4 | 0.1971m | 0.000000rad | 2→3 | 0/0 | 0 |
| B 南侧→北侧 | 7→2→3→5 | 0.1969m | 0.0289rad | 2→3 | 0/0 | 0 |
| 行驶中请求孤立终点8 | 先7→2→3→5，再请求8 | 不适用 | 不适用 | 未强行继续 | 0/0 | 按预期停止 |

A 连续生成29个局部目标，B 为27个。局部目标最大轴向距离分别4.007、4.005m。路段切换由按序经过节点2、3及对应路段进度确认；实测与规划图均保存。A直行；B在第一路口右转、第二路口左转，选择北侧出口；均未跳过必经路口。备选分支查询1→6返回1→2→6，证明分支可被选中；7→5则选主干24.0代价，备选路线约32.62。**备选分支只验证选路查询，未执行第三条实车或仿真行驶路线**。

B实际最小转弯半径1.8937m，假设车体最小半径1.8922m；执行指令约束违反0，原地旋转0，倒车0，转向关节上限未超。A直行的巨大数值半径仅表示曲率接近0，不作为转弯测量。

**控制器原始请求的局限：**B有49条 RPP 请求超过物理曲率上限，既有保护器将其裁剪；实际指令和真值运动均在约束内。不能宣称 RPP 原始输出天然适用于阿克曼车，也不能移除保护器。进一步让路线/局部路径跟踪更保守仍是后续改进事项，未放宽车辆限制或既有容差。

不可达场景：车辆以约0.4m/s行驶2m后，请求无连通边的节点8。Route Server 返回 NO_VALID_ROUTE=405，生成器进入 FAILED、禁止继续转发运动命令并取消 FollowPath。根据录包接收时刻，相对首个 FAILED 状态，下一条零速约0.6ms、实际速度进入停止阈值约100.1ms、满足持续200ms确认约300.2ms。注意：请求开始 ROUTING 时就发出零速，因此这些数字**不是故障请求到首次保护触发的延迟，也不是底层超时延迟**；含状态20Hz量化与传输延迟。既有60ms watchdog未修改，其前次负载测试61.4–61.8ms触发证据继续有效。本轮不重新声称其为硬实时实车保证。

补充以不可达请求接收时刻为起点：首次零速约0.4ms，失败状态上报约39.8ms，实际停止约139.9ms，持续停止确认约340.0ms。零速先于失败状态，因为查询新路线时已主动暂停车辆。详见原实验 failure-timing.json；测量同样包含录包接收和50Hz速度采样误差，不能称为实车保护延迟。

局部规划连续失败3次会停止；控制器拒绝/中止、定位超时、离路、偏离路线、规划路径超局部范围也会停止并报告。**本轮实际注入的是不可达图场景；物理路障、连续局部规划失败、定位断流和生成器崩溃尚未专项注入**，不混称全部故障场景通过。
