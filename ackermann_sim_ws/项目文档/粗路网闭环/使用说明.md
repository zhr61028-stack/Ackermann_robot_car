# 小型粗路网闭环：先看演示，再运行

当前完成的是**路网选路→前方局部目标→Smac规划→RPP跟踪→虚拟车运动**的最小闭环。Route Server决定走哪些道路；局部规划器生成当前车体能走的路径。仍使用仿真真值和已知道路边界，没有校园经纬度或真实定位。

## 运行路线B：每次只做一步

1. 打开Ubuntu终端，任意目录执行下面一条。它加载现有Jazzy与工作区，只启动仿真，不安装软件、不改系统配置：

```bash
bash ${ACKERMANN_WS}/scripts/start_route.bash start:=B
```

正常：Gazebo和RViz打开，启动终端显示 `Managed nodes are active`。虚拟车在南侧道路起点。保留这个终端。

异常：等约15秒仍无此消息，保留最早报错；不要再开第二个同模式实例，不要盲目重装。未出现真值位置或TF时，先检查启动日志。

2. 新开第二个终端，任意目录执行一条，只提交北侧终点节点5。脚本自动加载ROS，不要求你记住source命令：

```bash
bash ${ACKERMANN_WS}/scripts/request_route.bash 5
```

正常：车先右转到主干道，再左转到北侧终点，约一分钟停车。RViz同时显示路线、局部目标和实际轨迹。到达不是要求车中心完全重合终点；原有位置容差0.20m，报告独立复核标准0.25m未放宽。

异常：若没有行驶，查看第一终端是否出现 FAILED、Route/Planner错误；不要直接给车辆速度强行绕过失败。界面Reset会影响已记录的真值恢复问题，不用Reset重新开始。

3. 结束时在第一终端按Ctrl+C，等进程退出再启动下一场景。

路线A：完整关闭后，将第一条中的 start:=B 改为 start:=A，第二条终点改为4。不能在已到达的车上直接测试另一种起点。

不可达演示：从B完整重启后，先请求5；车前进后请求8。节点8是断开的测试终点，系统应报告405并停车，不尝试绕过。它不是校园点位。

## 开发与证据复现

当前已构建。以后仅在源码有变化时，才在工作区目录加载Jazzy并正常colcon构建；不手改build/install。新增软件包是 src/ackermann_route/，原车辆参数和Nav2配置未改。

正式验证工具为 scripts/validate_route.py，**只提交最终节点，不驾驶中途路点**。运行时需要第二终端加载Jazzy并设置域84；输出必须选择一个全新目录，以免覆盖原证据。路线A用--goal 4，B用--goal 5，失败用--goal 5 --failure，加--video捕获实际Gazebo/RViz窗口。完整录包复核工具是 scripts/audit_route.py。本轮运行命令保存于报告的执行记录。

| 文件 | 用途 |
|---|---|
| src/ackermann_route/config/roads.yaml | 场地尺寸、道路边界、测试起点、局部目标设置 |
| src/ackermann_route/config/local_test_graph.geojson | 本地米制路网节点、有向边与分支代价，不是WGS-84 |
| src/ackermann_route/config/route_server.yaml | Route Server与平滑设置 |
| src/ackermann_sim/config/vehicle.yaml | 原车辆假设参数，待实测 |
| src/ackermann_nav/config/nav2.yaml | 沿用Smac/RPP前向配置 |

所有尺寸、车体能力仍是“仿真假设，待实测”。生成的地图/世界/YAML存于临时目录，运行中使用新生成资源；报告里的配置快照仅供查看，不能直接作为第二套参数源。

## 当前局限

RPP在转弯时部分原始指令需要既有保护器裁剪；实测执行结果符合车体约束，不可移除保护器。道路边界是已知测试地图，定位是仿真真值。真实校园粗图的WGS-84投影、GNSS/里程计融合、道路感知和安全链仍未完成。实车、传感器与外参信息需后续补齐。
